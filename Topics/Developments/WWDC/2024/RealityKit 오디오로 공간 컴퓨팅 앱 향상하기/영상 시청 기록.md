# 내용 정리

## 2:01 · Spatial audio

**RealityKit의 오디오는 기본이 공간 음향입니다.** `Entity.playAudio` 두어 줄이면 6DoF 렌더링, 물리 기반 거리 감쇠, 실제 주변 환경에서 실시간 시뮬레이션된 리버브가 전부 적용됩니다.

- 공간 재생되는 오디오는 스페이셜라이즈 직전에 **모노로 다운믹스**됩니다. 예상치 못한 다운믹스 아티팩트를 피하려면 애초에 모노 파일로 만드는 게 권장됩니다.

**`AudioFileResource.Configuration`**

- `shouldLoop` — 짧은 파일을 끊김 없이 반복. 루프용 파일은 seamless하게 저작해야 팝·클릭이 안 생깁니다.
- `shouldRandomizeStartTime` — 같은 파일을 여러 소스에서 재생할 때 시작 위치를 무작위로. 엔진 두 개에 같은 파일을 써도 소리가 겹쳐 들리지 않습니다. 리소스 절약 + 풍부한 결과.
- `loadingStrategy` — `.preload`(기본, 로딩 시 디코드) / `.stream`(디스크에서 실시간 디코드). 메모리는 아끼지만 지연이 생기므로 큰 앰비언트 파일에 적합.
- `mixGroupName` — 아래 믹스 그룹에서 사용.

**`AudioPlaybackController`** — `playAudio` / `prepareAudio`가 반환. 특정 사운드 인스턴스의 리모컨 역할.

- `gain` — 상대 데시벨. `-.infinity`가 무음, `0`이 기준 최대. 모든 소리는 0dB로 클램프됩니다.
- `fade(to:duration:)` — 루프 파일은 시작이 갑작스러우니 `-.infinity`로 시작해 1초간 페이드인하면 자연스러워집니다.
- `play` / `pause` / `stop` 트랜스포트 제어.

**`SpatialAudioComponent`**

- `directivity` — `.beam(focus:)` 는 0~1. 0은 무지향성(모든 방향 동일), 1에 가까울수록 좁은 빔이 되어 뒤쪽에서 더 작고 어둡게 들립니다. 예제는 0.25.
- 팁: 엔티티에 직접 재생하지 말고 **자식으로 오디오 소스 전용 `Entity`를 만들어** 거기서 재생하면, 그 엔티티만 회전시켜 소리가 나오는 방향(배기구 쪽)을 맞출 수 있습니다.
- `gain` — Component 프로토콜을 따르므로 커스텀 System에서 매 업데이트마다 갱신하기 좋습니다. 예제는 throttle 값(선형)을 데시벨(로그)로 매핑해 배기음 크기에 반영합니다.
- `distanceAttenuation` — rolloff factor. 1이 자연스러운 기본값, 2면 두 배 빨리 감쇠, 0.5면 절반 속도로 감쇠. 예제는 조종석 음악에 4를 줘서 우주선이 아주 가까이 왔을 때만 들리게 만듭니다.

**`AudioGeneratorController`** — 파일 대신 콜백에서 오디오 버퍼를 직접 써넣는 `playAudio` 변형.

- 반환된 컨트롤러를 **앱이 반드시 붙들고 있어야** 스트리밍이 계속됩니다.
- 작성한 버퍼도 파일 재생과 똑같이 취급됩니다. Spatial / Ambient / Channel 오디오 컴포넌트로 렌더링 제어 가능.
- Apple 제공 audio unit, 직접 만든 audio unit, 자체 오디오 엔진 출력을 모두 흘려보낼 수 있습니다. 예제는 throttle 값으로 오실레이터를 구동하는 커스텀 `AudioUnitTurbine`을 써서 보이지 않는 터빈 소리를 만듭니다.
- 절차: `instantiate()` → 출력 포맷 설정 → 렌더 리소스 할당 → `internalRenderBlock` 캡처 → 제너레이터 콜백에서 호출.

## 11:43 · Collisions

`CollisionEvents.Began`을 받아 충돌한 두 엔티티 정보로 소리를 재생합니다. 그냥 파일 하나를 트는 것에서 시작해 세 단계로 다듬습니다.

1. **`AudioFileGroupResource`** — 오디오 파일 리소스 배열로 만들고, `playAudio`를 호출할 때마다 그중 하나가 무작위로 재생됩니다. 같은 사건의 미묘한 변주들을 넣어두면 충돌음이 기계적으로 반복되지 않습니다.
2. **속도 반영** — 반환된 `AudioPlaybackController`의 `gain`을 두 엔티티의 속도로 계산해 설정. 정면 고속 충돌은 강하게, 느린 접촉은 약하게.
3. **재질 조합** — `AudioMaterial` enum과 커스텀 `AudioMaterialComponent`를 정의해 각 오브젝트에 붙입니다(우주선=plastic, 소행성=rock, 환경=concrete/wood/metal/glass). 충돌 시 두 재질의 쌍으로 인덱싱된 `AudioFileGroupResource`를 골라 재생.

**실제 사물과의 충돌**도 같은 구조로 확장됩니다. ARKit 씬 리컨스트럭션 메시에서 충돌한 face를 찾고 → 그 face의 mesh classification을 읽고 → 커스텀 `AudioMaterial`로 매핑. 이러면 테이블, iMac, 의자에 부딪힐 때 각각 다른 소리가 납니다.

## 16:57 · Reverb presets

가상 환경에 들어가면 조명이 바뀌듯 음향도 바뀌어야 합니다. **`ReverbComponent`** 를 엔티티 계층 어딘가에 두기만 하면 됩니다. Reality Composer Pro에서 저작하거나 RealityKit API로 직접 설정.

- **한 번에 하나의 리버브만 활성화**됩니다.
- visionOS 1에서는 모든 공간 오디오가 실제 공간의 실시간 시뮬레이션 음향으로만 울렸습니다. 패스스루로 실제 방이 보이는 mixed immersion에서는 이게 맞습니다 — 보이는 대로 들려야 하니까요.
- visionOS 2의 리버브 프리셋은 progressive / full immersive 공간에서 사용자를 다른 세계로 데려갑니다. **Progressive**는 몰입도 수준에 따라 실제 음향과 프리셋을 블렌딩하고, **Full**은 프리셋만 적용합니다.

## 18:24 · Immersive music

우주선은 앞뿐 아니라 사방으로 날아다니고 행성이 뒤에서 생기기도 합니다. 그래서 음악은 어디를 보든 존재하되 **뚜렷한 정면 방향이 없어야** 합니다.

- **쿼드라포닉(4채널) 레이아웃**을 사용. 네 채널이 사용자 주위에 등간격으로 퍼져서, 영화용 멀티채널 레이아웃과 달리 두드러지는 정면이 없습니다. 채널 간 신호 분포도 고르게 저작해 어디를 봐도 균형이 유지되게 합니다.
- **멀티채널 파일은 채널 레이아웃이 파일 안에 기록되어 있어야** RealityKit이 각 채널을 올바른 각도에서 렌더링합니다. 안 그러면 동작하지 않습니다.
- **`AmbientAudioComponent`** — 3DoF로 렌더링. 소스와 머리의 회전은 반영하지만 **이동은 반영하지 않습니다**. 채널이 월드에 고정된 방향에서 오므로 머릿속에서 나는 느낌이 안 납니다.
- 음악 파일도 seamless 루프로 저작하고, 파일이 크므로 `.stream` 로딩 전략을 씁니다.

## 20:41 · Mix groups

사용자가 카테고리별 음량을 직접 조절하게 해주는 기능입니다.

- 리소스의 `AudioFileResource.Configuration`에서 `mixGroupName`을 `"Music"` 같은 이름으로 지정합니다. 이 이름을 공유하는 모든 리소스가 한 번에 제어됩니다.
- `AudioMixGroupsComponent`를 들고 있을 엔티티를 하나 만들고, UI에서 레벨이 바뀔 때 `AudioMixGroup`을 만들어 `gain`을 설정한 뒤 컴포넌트를 갱신합니다.
- 역시 Component 프로토콜을 따르므로 UI 대신 커스텀 System에서 갱신해도 됩니다.
