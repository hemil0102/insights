# 성향 보기 (`/mbti`)

## 이 문서의 목적

`/thoughts`, `/me`, `/people`이 재료를 모은다. 여기는 **모인 것을 꺼내 보는 자리**다.

새로 점수를 매기는 곳이 아니다. **검사를 실시하는 곳은 더더욱 아니다.** 이미 쌓인 행동 일화를 읽어서 지금 무엇이 보이고 무엇이 아직 안 보이는지를 말한다.

---

## 가장 중요한 규칙

**빈 축을 채우지 않는다.**

`? ? ? J` 가 나오면 그대로 `? ? ? J` 라고 말한다. 네 글자를 만들어주고 싶은 유혹이 이 스킬의 가장 큰 실패 모드다. 근거가 없는 자리는 **"아직 안 물어본 자리"** 라고 부른다. "해당 없음"이나 "중간형"이 아니다.

**유형으로 사람을 규정하지 않는다.** "너는 J라서 이래" 는 금지. 말할 수 있는 것은 "J 쪽 일화가 네 패싯에서 나왔다" 까지다.

**진로·궁합·미래를 예언하지 않는다.** 유형으로 직업이나 관계를 추천하지 않는다. 근거가 없다.

---

## 먼저 아카이브를 찾는다

이 스킬은 **인사이트 아카이브**를 읽어야 동작한다. 저장소 안에서 실행될 수도 있고 아닐 수도 있으므로 **경로를 가정하지 않는다.**

찾는 순서 —

1. **현재 작업 폴더**에 `Experiences/성향 누적.md` 가 있으면 그것을 쓴다
2. 없으면 **연결된 폴더들**을 훑어 `Experiences/성향 누적.md` 를 가진 폴더를 찾는다. Cowork에서는 `device_bash` 로:
   ```bash
   ls -d "$HOME"/mnt/*/ | while read d; do [ -f "$d/Experiences/성향 누적.md" ] && echo "$d"; done
   ```
   *(폴더 이름이 한글이면 `find -name` 이 macOS의 유니코드 정규화 차이로 빗나간다. 위처럼 glob으로 훑을 것.)*
3. 그래도 못 찾으면 **추측하지 말고 물어본다** — "인사이트 폴더가 이 세션에 연결돼 있지 않아. 연결해줄래?" 없는 상태로 답을 지어내지 않는다

찾았으면 읽는다 —

| 파일 | 용도 |
|---|---|
| `Experiences/성향 누적.md` | 본체. 집계·패싯 표·관찰 로그 |
| `Experiences/생각/` 최근 1~2개월 | 마지막 집계 이후 새 일화가 있는지 |
| `Experiences/연보.md` | 필요할 때만 |

**읽기 전에 답하지 않는다.** 기억으로 말하면 숫자가 틀린다.

`Experiences/**` 는 git-crypt로 암호화된다. 복호화된 상태로 마운트돼 있으면 평문으로 읽히고, 아니면 바이너리로 보인다. **바이너리로 보이면 잠긴 것이니 그대로 말하고 멈춘다.**

## 출력 형식 — 순서를 지킨다

### ① 한 줄

지금 이 파일이 말할 수 있는 것 한 문장. 과장하지 않는다.

> 예 — "근거 25개 중 확정된 축은 하나야. J/P만 확정이고, 그것도 시기 사이에 뒤집혔어."

### ② 코드

시기별로 나눠서. 합산하지 않는다.

```
중학생 (1999–2001)   ? ? ? p     근거 12
현재 (2026, 40세)    ? ? ? J     근거 13
```

### ③ 축별 표

패싯 수와 표를 같이 보여준다. 일화 수만 보여주면 왜곡된다.

| 축 | 근거 패싯 | 표 | 상태 |
|---|---|---|---|

동점(무효표)이 있으면 반드시 표시한다. **동점은 애매함이 아니라 정보다.**

### ④ 지난번 이후 달라진 것

없으면 "달라진 것 없음"이라고 쓴다. 억지로 찾지 않는다.

### ⑤ 축 바깥에서 반복되는 것

파일의 해당 절을 근거 횟수와 함께 보여준다. **대개 여기가 네 글자보다 쓸모 있다.**

### ⑥ 명언 한 줄

기록에 실제로 나온 주제와 연결되는 문장 하나.

**규칙 —**
- **실존 인물의 실제 문장만.** 출처(저자·출전)를 함께 적는다
- **확신이 없으면 인용하지 않는다.** 대신 **기록 안에 있는 그 자신의 문장**을 인용한다. 그게 지어낸 인용보다 언제나 낫다
- 그날의 주제와 연결한다. 아무 데나 붙는 좋은 말은 쓰지 않는다
- 한 줄 붙여 왜 이 문장인지 말한다. 설교하지 않는다

### ⑦ 해볼 일 두 개

**하나는 기록을 채우는 것, 하나는 반복되는 것에 대응하는 것.**

- 오늘, 30분 안에, 혼자 할 수 있는 크기
- 제안까지만 한다. 안 하겠다고 하면 그걸로 끝이고 다시 권하지 않는다
- 「축을 확인하기 위한 질문」을 그에게 시키지 않는다. 그건 자기보고가 되어 규칙 위반이다. 대신 **그냥 해보면 재료가 생기는 활동**을 고른다

> 나쁜 제안 — "네가 S인지 N인지 스스로 생각해봐"
> 좋은 제안 — "이번 주에 뭔가 새로 만들거나 고친 게 있으면 그 과정을 세 줄로 적어둬"

### ⑧ 다음에 채울 것

파일의 「다음에 채울 것」 표를 그대로 보여준다. 우선순위 1번만 강조한다.

---

## 하지 않을 것

- **검사 권유.** "정확히 알려면 검사를 해봐"는 이 파일의 전제를 무너뜨린다
- **네 글자 완성.** 근거 없는 자리를 추정으로 채우기
- **유형 기반 예언.** 직업, 궁합, 적성
- **감정 서술로 점수 매기기.** "속상해"는 0점. 규칙은 본체 파일에 있다
- **좋은 말로 마무리하기.** "그래도 넌 좋은 사람이야" 류는 근거가 없으면 쓰지 않는다
- **지어낸 인용.** 출처를 못 대면 쓰지 않는다

## 실행 절차

| 입력 | 하는 일 |
|---|---|
| `/mbti` | 위 ①~⑧을 순서대로 출력 |
| `/mbti 갱신` | 최근 생각 로그를 다시 읽어 새 일화를 패싯에 배정하고 본체 파일을 갱신한 뒤 출력 |
| `/mbti 패싯` | 20개 패싯 표 전체를 보여준다. 빈 패싯이 어디인지 보는 용도 |
| `/mbti 규칙` | 채점 규칙 4단계만 보여준다 |

### 갱신할 때

`Experiences/성향 누적.md` 의 **채점 규칙 4단계를 그대로 따른다.** 이 스킬은 규칙을 새로 만들지 않는다.

- 일화 → 패싯 → 축 → 코드
- 출처별 상한(`인터뷰` 2점 / `생각` 1점 / `실행` 2점)
- 패싯 배정이 애매하면 `미배정`으로 두고 축 판정에서 제외
- 갱신하면 「현재 판정」, 「패싯 표」, 「관찰 로그」 세 곳의 숫자가 **모두** 맞아야 한다. 하나만 고치면 파일이 거짓말을 한다

**갱신 후에는 반드시 검산한다.** 이 폴더의 `verify.py` 가 관찰 로그를 직접 파싱해서 패싯 표와 코드를 다시 계산한다.

```bash
python3 <이 스킬 폴더>/verify.py
```

`verify.py` 도 같은 방식으로 아카이브를 찾는다. 스킬이 계정 스킬로 저장돼 저장소 밖에서 실행돼도 동작한다.

출력이 파일의 「현재 판정」·「패싯 표」와 다르면 **파일 쪽이 틀린 것이다.** 손으로 센 숫자를 믿지 않는다. 패싯 이름을 잘못 적으면 `!! 패싯 이름 불일치` 로 잡힌다.

### 실행 환경

Cowork에서는 `device_bash` 로 `Experiences/` 를 직접 읽고 쓴다. Claude Code에서는 `Read`/`Write`.
